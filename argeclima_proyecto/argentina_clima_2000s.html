🌐 Fuentes de datos utilizadas

Esta demo cita las fuentes que se pasaron para el proyecto. Para datos reales en vivo hay que integrarlas por atras (ver seccion siguiente), ya que ninguna ofrece un endpoint publico apto para llamarse directo desde el navegador de una pagina publicada:

  • Servicio Meteorologico Nacional (SMN) — descarga de observaciones horarias/diarias por estacion: smn.gob.ar/descarga-de-datos (archivos CSV/TXT de descarga manual, sin API key).
  • INTA — Red SIGA — estaciones agrometeorologicas del INTA: siga.inta.gob.ar/#/data.
  • OHMC (Obs. Hidrometeorologico de Cordoba) — panel de datos: meteocordoba.ohmc.com.ar — ojo: esa URL es un panel de administracion Django, no un endpoint de API publico; para usarla en serio hay que pedirle acceso/API al OHMC.
  • Weather Underground (PWS API) — red de estaciones personales; requiere API key propia y llamado desde servidor, nunca desde el HTML publico.

🔧 Como conectar datos reales

La pagina ya esta armada para recibir datos reales: solo hay que reemplazar el array STATIONS en el codigo por datos que vengan de un JSON. La forma prolija de hacerlo:

  1. Un script propio (por ejemplo en Python, corriendo en tu compu o en un servidor tuyo) llama a SMN/INTA/OHMC/Wunderground con tu API key guardada como variable de entorno, nunca escrita en el HTML.
  2. Ese script guarda el resultado en un archivo datos.json con esta forma: [{"name":"...","province":"...","source":"SMN","max":30.1,"min":12.4}, ...]
  3. Subis ese JSON a algun hosting propio (o lo pegas a mano) y la pagina lo carga y arma el ranking solita.

Te dejo un script de Python de arranque (fetch_estaciones.py) armado con esta misma logica, para que lo corras vos con tu API key.
